# Logistic Regression, In Full Depth

Despite the name, logistic regression is a *classification* algorithm, not a regression one — it predicts a probability, then a class. It's the natural next step after [Linear Regression](/docs/machine-learning/linear-regression): same linear core, adapted to output something that behaves like a probability.

<ELI5>

Imagine sorting emails into "spam" or "not spam." You don't want a flat yes/no — you want a confidence, like "92% sure this is spam," so obviously-spam and borderline cases can be treated differently. Logistic regression does exactly that: it takes the same "weighted sum of features" idea as linear regression, but instead of outputting a raw number that could be anything, it squashes that number into a value between 0 and 1 that behaves like a real probability. Only after that does it draw a line — probability above 50%, call it spam; below, call it not spam.

Everything below is that same idea, made exact: the actual squashing function, the actual loss that makes training it work, and why that loss — not the obvious one — is the right choice.

</ELI5>

## What Is Logistic Regression?

Linear regression predicts an unbounded real number. That's wrong for classification — if you're predicting "is this email spam?", you want an output between 0 and 1 that behaves like a probability, not a number that could be -40 or +1000.

Logistic regression fixes this with one change: take the linear regression output and squash it through the **sigmoid function**.

## The Sigmoid Function

$$\sigma(z) = \frac{1}{1 + e^{-z}}, \qquad z = \mathbf{w}^T\mathbf{x} + b$$

<img src={__migratedImg0} alt="The sigmoid function, mapping any real number to (0, 1), with a decision threshold at z=0" style={{maxWidth: '100%'}} />

Read directly off the curve: as $z \to +\infty$, $\sigma(z) \to 1$; as $z \to -\infty$, $\sigma(z) \to 0$; at $z=0$, $\sigma(z) = 0.5$ exactly. No matter what real number $z = \mathbf{w}^T\mathbf{x}+b$ comes out of the linear part, $\sigma(z)$ always lands in $(0,1)$ — a valid probability. The full hypothesis:

$$\hat{p} = \sigma(\mathbf{w}^T\mathbf{x} + b)$$

$\hat{p}$ is interpreted as $P(y=1 \mid \mathbf{x})$. To get an actual class prediction, threshold it — conventionally $\hat{y} = 1$ if $\hat{p} \geq 0.5$, else $\hat{y} = 0$ (equivalently: predict class 1 whenever $z \geq 0$).

## Why Not Just Use MSE Loss?

You could plug $\hat{p}$ into the same [MSE cost function](/docs/machine-learning/linear-regression#2-the-cost-function-mean-squared-error) from linear regression. It would technically run — but the resulting cost surface is **non-convex** in $(\mathbf{w}, b)$ when combined with the sigmoid, full of local minima that gradient descent can get stuck in. Logistic regression uses a different loss specifically chosen to stay convex.

Don't take that on faith — switch the Studio above to **Gradient Descent Lab** mode and toggle the **Loss function** between Cross-Entropy and MSE (naive). Both start from the same deliberately bad initialization: Cross-Entropy steadily escapes it; MSE-on-sigmoid gets stuck almost immediately and barely moves for hundreds of steps — the loss landscape panel shows exactly why: a visibly bumpier, flatter-near-the-wrong-answer surface instead of cross-entropy's clean bowl.

## The Cost Function: Binary Cross-Entropy

$$J(\mathbf{w}, b) = -\frac{1}{n}\sum_{i=1}^n \left[y^{(i)}\log(\hat{p}^{(i)}) + (1-y^{(i)})\log(1-\hat{p}^{(i)})\right]$$

This looks intimidating but is simple per-example: only one of the two terms is ever "active," because $y^{(i)}$ is either 0 or 1.

- If $y^{(i)} = 1$: the second term vanishes ($1-y^{(i)}=0$), leaving $-\log(\hat{p}^{(i)})$. This is small when $\hat{p}^{(i)}$ is close to 1 (correct, confident) and blows up toward $+\infty$ as $\hat{p}^{(i)} \to 0$ (confidently wrong) — exactly the penalty behavior you want.
- If $y^{(i)} = 0$: the first term vanishes, leaving $-\log(1-\hat{p}^{(i)})$ — small when $\hat{p}^{(i)}$ is close to 0, blowing up as $\hat{p}^{(i)} \to 1$.

**This is exactly cross-entropy** from [Probability & Statistics](/docs/mathematics-for-ai/probability-statistics#entropy-cross-entropy-and-kl-divergence), specialized to two classes — and it's not an arbitrary design choice: minimizing this loss is precisely Maximum Likelihood Estimation for a Bernoulli-distributed target (see [MLE vs MAP](/docs/mathematics-for-ai/probability-statistics#mle-vs-map)). Unlike MSE-on-sigmoid, this cost function *is* convex in $(\mathbf{w}, b)$, so gradient descent is guaranteed to find the global minimum.

<GoDeeper title="Go deeper: derive cross-entropy from the Bernoulli likelihood">

Same move as [Linear Regression's Gaussian-noise derivation](/docs/machine-learning/linear-regression#2-the-cost-function-mean-squared-error), with a different distribution. A single label $y^{(i)} \in \{0,1\}$ is Bernoulli-distributed with parameter $\hat{p}^{(i)}$ — the compact way to write "probability $\hat{p}^{(i)}$ that $y^{(i)}=1$, probability $1-\hat{p}^{(i)}$ that $y^{(i)}=0$" as one formula is:

$$P\left(y^{(i)} \mid x^{(i)}\right) = \left(\hat{p}^{(i)}\right)^{y^{(i)}} \left(1-\hat{p}^{(i)}\right)^{1-y^{(i)}}$$

Check it: when $y^{(i)}=1$, the second factor becomes $(\cdot)^0=1$, leaving just $\hat{p}^{(i)}$; when $y^{(i)}=0$, the first factor vanishes the same way, leaving $1-\hat{p}^{(i)}$ — exactly the two cases, folded into one expression.

For $n$ independent examples, the likelihood is the product across all of them, and the log-likelihood turns that product into a sum:

$$\log L(\mathbf{w}, b) = \sum_{i=1}^{n}\left[y^{(i)}\log\hat{p}^{(i)} + \left(1-y^{(i)}\right)\log\left(1-\hat{p}^{(i)}\right)\right]$$

Maximizing $\log L$ is identical to minimizing $-\log L$, and dividing by the constant $n$ doesn't move the minimizer — so minimizing $-\frac{1}{n}\log L(\mathbf{w},b)$ is *exactly* $J(\mathbf{w},b)$ as written above. Binary cross-entropy isn't a separately invented penalty that happens to look reasonable; it *is* the negative log-likelihood of the Bernoulli model, the direct analogue of how Gaussian noise produces squared error.

</GoDeeper>

## Deriving the Gradient

This is where something elegant happens. Working through the chain rule — differentiating the log-loss with respect to $z$, then $z$ with respect to $w_j$ — the sigmoid's own derivative ($\sigma'(z) = \sigma(z)(1-\sigma(z))$) cancels almost entirely against terms from the log-loss derivative, leaving:

$$\frac{\partial J}{\partial w_j} = \frac{1}{n}\sum_{i=1}^n \left(\hat{p}^{(i)} - y^{(i)}\right)x_j^{(i)}$$

<GoDeeper title="Go deeper: watch the cancellation happen, term by term">

Work with one example at a time — drop the $(i)$ superscript and the $\frac1n$ average, and restore both at the end. Let $\ell = -\left[y\log\hat{p} + (1-y)\log(1-\hat{p})\right]$, with $\hat{p}=\sigma(z)$ and $z=\mathbf{w}^T\mathbf{x}+b$. Three chain-rule steps: $\ell \to \hat{p} \to z \to w_j$.

**Step 1 — $\dfrac{\partial \ell}{\partial \hat{p}}$:** differentiate each log term directly ($\frac{d}{dp}\log p = \frac1p$; $\frac{d}{dp}\log(1-p) = \frac{-1}{1-p}$):

$$\frac{\partial \ell}{\partial \hat{p}} = -\frac{y}{\hat{p}} + \frac{1-y}{1-\hat{p}}$$

**Step 2 — $\dfrac{\partial \hat{p}}{\partial z} = \sigma'(z)$:** worth deriving this once too, from $\sigma(z) = (1+e^{-z})^{-1}$:

$$\sigma'(z) = -(1+e^{-z})^{-2}\cdot(-e^{-z}) = \frac{e^{-z}}{(1+e^{-z})^2} = \underbrace{\frac{1}{1+e^{-z}}}_{\sigma(z)}\cdot\underbrace{\frac{e^{-z}}{1+e^{-z}}}_{1-\sigma(z)} = \hat{p}(1-\hat{p})$$

**Step 3 — multiply and watch it collapse:**

$$\frac{\partial \ell}{\partial z} = \frac{\partial \ell}{\partial \hat{p}}\cdot\frac{\partial \hat{p}}{\partial z} = \left(-\frac{y}{\hat{p}}+\frac{1-y}{1-\hat{p}}\right)\hat{p}(1-\hat{p}) = -y(1-\hat{p}) + (1-y)\hat{p} = -y+y\hat{p}+\hat{p}-y\hat{p} = \hat{p}-y$$

The $\hat{p}$ in the denominator of the first term cancels exactly against the $\hat{p}$ multiplied in from $\sigma'(z)$; same for $(1-\hat{p})$ in the second term. Everything the log-loss derivative and the sigmoid derivative each contributed disappears, leaving the strikingly plain $\hat{p}-y$ — that's the "elegant" cancellation the prose above promises, not a hand-wave.

**Step 4 — finish the chain:** $\dfrac{\partial z}{\partial w_j} = x_j$ (identical to linear regression), so $\dfrac{\partial \ell}{\partial w_j} = (\hat{p}-y)x_j$. Restore the $(i)$ superscripts, sum over $n$ examples, divide by $n$ — exactly the formula above.

</GoDeeper>

**This is the identical formula shape as linear regression's gradient** (see [Linear Regression — Section 3](/docs/machine-learning/linear-regression#3-deriving-the-gradient-step-by-step)) — "error times input," summed over examples — even though the loss function and the model's output are completely different. This isn't a coincidence: it's a general property of combining a sigmoid/softmax output with cross-entropy loss (the same clean gradient shape reappears in [neural network classifiers](/docs/deep-learning/training-deep-networks) and in LLM next-token prediction).

The gradient descent update is then identical in form to linear regression's:

$$w_j \leftarrow w_j - \alpha \cdot \frac{1}{n}\sum_i \left(\hat{p}^{(i)} - y^{(i)}\right)x_j^{(i)}$$

## The Decision Boundary

Because $z = \mathbf{w}^T\mathbf{x}+b$ is linear, and the threshold is at $z=0$, the boundary between predicted classes is a **straight line** (or a flat hyperplane in higher dimensions):

<img src={__migratedImg1} alt="Logistic regression decision boundary separating two classes in 2D feature space" style={{maxWidth: '100%'}} />

This is the central limitation of plain logistic regression: it can only separate classes that are (approximately) linearly separable. Data that needs a curved boundary requires either engineered polynomial features, or a fundamentally different model (see [SVM](/docs/machine-learning/supervised-learning#support-vector-machines) with a kernel, or a neural network).

## Regularized Logistic Regression

Exactly like linear regression, logistic regression overfits with too many features relative to data — and the same fix applies directly: add an L2 (or L1) penalty to $J(\mathbf{w}, b)$ above, identical in form to [Ridge](/docs/machine-learning/ridge-regression#the-ridge-cost-function) or [Lasso](/docs/machine-learning/lasso-regression#the-lasso-cost-function)'s penalty term. This is in fact the *default* behavior in most libraries (e.g. scikit-learn regularizes logistic regression by default) — unregularized logistic regression is the exception, not the norm, in practice.

## Multi-Class: Softmax Regression

For more than two classes, the sigmoid generalizes to the **softmax function**, and binary cross-entropy generalizes to categorical cross-entropy — the exact loss used to train every classifier's output layer in [Deep Learning](/docs/deep-learning/roadmap), including next-token prediction in every LLM (see [Training Pipeline](/docs/llms-genai/training-pipeline)).

## Minimal Implementation

```python
import numpy as np

def sigmoid(z):
    return 1 / (1 + np.exp(-z))

def fit_logistic_regression(X, y, lr=0.1, epochs=1000):
    n, d = X.shape
    w = np.zeros(d)
    b = 0.0
    for _ in range(epochs):
        z = X @ w + b
        p_hat = sigmoid(z)
        error = p_hat - y                   # identical shape to linear regression's gradient
        dw = (1 / n) * X.T @ error
        db = (1 / n) * np.sum(error)
        w -= lr * dw
        b -= lr * db
    return w, b

def predict(X, w, b, threshold=0.5):
    return (sigmoid(X @ w + b) >= threshold).astype(int)
```
