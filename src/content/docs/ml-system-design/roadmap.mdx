# ML System Design — Roadmap

How to take a model and turn it into a working, scalable production system. Framed around a repeatable 9-step formula plus worked problem categories.

## The [9-Step Framework](/docs/ml-system-design/the-9-step-framework)

<NineStepPipelineDiagram />

1. [x] **Problem formulation** — translate a business need into an ML problem
2. [x] **Metrics** — offline metrics (what you optimize in dev) vs online metrics (what you measure in production, e.g. CTR, retention)
3. [x] **Architectural components** — sketch the MVP: data → features → model → serving
4. [x] **Data collection & preparation** — sourcing, labeling, cleaning
5. [x] **Feature engineering** — what signals actually predict the target
6. [x] **Model development & offline evaluation** — pick a model class, validate offline
7. [x] **Prediction service** — batch vs online serving, latency budgets
8. [x] **Online testing & deployment** — A/B tests, shadow deployment, canary rollout
9. [x] **Scaling, monitoring, and updates** — drift detection, retraining cadence, rollback plans

## Common Problems & SOTA Solutions

<ProblemSolutionMapDiagram />

- [x] **Training-serving skew** → shared feature pipelines, feature stores
- [x] **Cold start** (new users/items) → content-based fallback, exploration strategies
- [x] **Feedback loops biasing the model** → randomized exploration, counterfactual evaluation
- [x] **Model staleness / concept drift** → monitoring dashboards, scheduled retraining, online learning
- [x] **Scaling inference to millions of requests** → caching, batching, model distillation, horizontal scaling
