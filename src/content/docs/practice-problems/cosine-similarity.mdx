# Cosine Similarity From Scratch

**Difficulty: Easy** · Concept: [Word Embeddings — The Distributional Hypothesis](/docs/nlp/word-embeddings#the-core-idea-the-distributional-hypothesis)

$$\cos(\theta) = \frac{a \cdot b}{\|a\| \, \|b\|}$$

Cosine similarity measures how aligned two vectors are in *direction*, ignoring magnitude entirely — `1` means pointing the same way, `0` means orthogonal (unrelated), `-1` means pointing opposite ways. This is *the* standard way to compare embeddings — [word embeddings](/docs/nlp/word-embeddings), sentence embeddings, and every vector database similarity search on this site all default to it, precisely because magnitude in embedding space usually reflects something irrelevant (like word frequency) while direction reflects meaning.

**Your task**: implement `cosine_similarity(a, b)` for two equal-length lists of numbers, without NumPy.

<Solution>

```python
import math

def cosine_similarity(a, b):
    dot = sum(x * y for x, y in zip(a, b))
    norm_a = math.sqrt(sum(x ** 2 for x in a))
    norm_b = math.sqrt(sum(y ** 2 for y in b))
    return dot / (norm_a * norm_b)
```

The numerator is exactly [Dot Product](/docs/practice-problems/dot-product); the denominator normalizes by each vector's own length (its L2 norm), which is what strips magnitude out of the comparison entirely — `[3, 4]` and `[6, 8]` are the same direction scaled by 2, and both give a cosine similarity of exactly `1.0` despite one vector being twice as long as the other. `[1, 0]` vs `[0, 1]` (perpendicular) gives `0.0`, and `[1, 0]` vs `[-1, 0]` (opposite) gives `-1.0` — the three landmark values worth having memorized.

In practice you'd use `numpy`'s vectorized dot/norm, or for embedding search at scale, an approximate-nearest-neighbor index (see [Vector Databases](/docs/databases/roadmap)) that never computes most pairwise similarities explicitly at all — but the definition here is exactly what those systems are optimizing around.
