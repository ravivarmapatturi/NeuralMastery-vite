# Determine a Two-Phase Commit Outcome

**Rank #463** · Difficulty: **Easy** · Stage: **Stage 8: RAG, Agents, MCP & Distributed Systems** · Category: **Agents, MCP & Systems**

Implement `two_phase_commit_outcome(votes)`, the coordinator's final decision rule in Two-Phase Commit -- every participant must unanimously agree before a transaction commits, and any single "no" (including a timeout) forces the whole transaction to abort. Prerequisite: `agents-mcp-systems-prob-32`.

<PracticePlayground problemId="agents-mcp-systems-prob-33" />

<Solution>

```python
def two_phase_commit_outcome(votes):
    if not votes:
        raise ValueError("votes must be non-empty")
    return "commit" if all(v is True for v in votes) else "abort"
```

A coordinator timeout is deliberately treated identically to an explicit "no" -- 2PC has no way to distinguish "the participant is slow" from "the participant failed," so the only safe assumption when a vote never arrives is to abort, never to optimistically commit.

</Solution>
