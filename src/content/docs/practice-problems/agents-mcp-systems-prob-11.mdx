# Deterministic Canary Rollout Router

**Rank #441** · Difficulty: **Medium** · Stage: **Stage 8: RAG, Agents, MCP & Distributed Systems** · Category: **Agents, MCP & Systems**

Implement `route_canary(request_id, canary_percentage)`, the deterministic hash-based routing a canary/blue-green rollout uses to decide which model or service version a given request sees -- the same request_id must land on the same side of the split every time, or a user would flicker between old and new behavior mid-session. Prerequisite: `agents-mcp-systems-prob-10`.

<PracticePlayground problemId="agents-mcp-systems-prob-11" />

<Solution>

```python
import hashlib

def route_canary(request_id, canary_percentage):
    if not (0 <= canary_percentage <= 100):
        raise ValueError("canary_percentage must be between 0 and 100")
    digest = hashlib.md5(request_id.encode()).hexdigest()
    bucket = int(digest, 16) % 100
    return "canary" if bucket < canary_percentage else "stable"
```

Hashing the identity into a bucket (instead of `random.random() < p`) is what makes the split sticky -- the same user keeps hitting the same variant on every request, which is required for any rollout that has session-visible behavior differences.

</Solution>
