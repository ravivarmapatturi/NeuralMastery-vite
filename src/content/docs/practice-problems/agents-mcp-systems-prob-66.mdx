# Track MCP Asynchronous Request Progress

**Rank #496** · Difficulty: **Hard** · Stage: **Stage 8: RAG, Agents, MCP & Distributed Systems** · Category: **Agents, MCP & Systems**

Implement `track_mcp_progress(initial_requests, notifications)`. Long-running MCP tools (such as database migrations or batch indexing) emit `notifications/progress` events referencing a `progressToken`. Given `initial_requests` (mapping `request_id` to a dict with `token` and `total` expected units of work) and a chronological list of `notifications` (each with `token`, `progress`, and optional `total`), update each request's progress state. If a notification includes an updated `total`, adopt it. Clamp `progress` to never exceed `total`. Compute percentage complete as `round((progress / total) * 100.0, 1)` (or `100.0` if `total == 0`). Return a dictionary `{request_id: {"progress": p, "total": t, "percent": pct, "completed": (p >= t)}}` sorted by `request_id`. Prerequisite: `agents-mcp-systems-prob-65`.

<Solution>

```python
def track_mcp_progress(initial_requests, notifications):
    token_to_req = {}
    state = {}
    for req_id, info in initial_requests.items():
        token = info["token"]
        token_to_req[token] = req_id
        state[req_id] = {
            "progress": 0,
            "total": info["total"]
        }
        
    for n in notifications:
        tok = n["token"]
        if tok in token_to_req:
            rid = token_to_req[tok]
            if "total" in n and n["total"] is not None:
                state[rid]["total"] = n["total"]
            state[rid]["progress"] = min(n["progress"], state[rid]["total"])
            
    result = {}
    for rid in sorted(state.keys()):
        prog = state[rid]["progress"]
        tot = state[rid]["total"]
        pct = round((prog / tot) * 100.0, 1) if tot > 0 else 100.0
        result[rid] = {
            "progress": prog,
            "total": tot,
            "percent": pct,
            "completed": prog >= tot
        }
    return result
```

### Key Concept: MCP progress tokens decouple asynchronous operation tracking from synchronous request-response lifecycles, enabling cooperative cancellation and progress bars.

**Constraints**:
- initial_requests maps request_id to `{'token': str, 'total': int}`.
- notifications contains `{'token': str, 'progress': int, optional 'total': int}`.
- progress is clamped to [0, total].
- percent is rounded to 1 decimal place.
- Output dictionary keys must be sorted alphabetically.
