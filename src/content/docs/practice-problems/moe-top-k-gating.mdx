# Mixture-of-Experts Top-K Gating From Scratch

**Difficulty: Medium** · Concept: [Foundation Model Internals — Mixture of Experts (MoE)](/docs/llms-genai/foundation-model-internals#mixture-of-experts-moe)

A Mixture-of-Experts layer has many separate "expert" sub-networks, but only routes each token through a small number of them (`k`, often 1 or 2) instead of all of them — a router produces one logit per expert, and only the top-`k` experts actually run, each weighted by how confident the router was in it. This is the real, practical trick that lets a model have a huge total parameter count (all the experts combined) while keeping the compute cost per token close to a much smaller dense model, since most experts stay unused for any given token.

**Your task**: implement `moe_top_k_gating(logits, k)` for a 1D array of per-expert router logits (one token), returning the indices of the top-`k` experts and their gating weights, softmaxed over *just those k experts* (not the full expert set).

<Solution>

```python
import numpy as np

def moe_top_k_gating(logits, k):
    top_idx = np.argsort(logits)[::-1][:k]
    top_logits = logits[top_idx]
    top_logits = top_logits - np.max(top_logits)  # numerically stable, same trick as softmax
    weights = np.exp(top_logits)
    weights /= weights.sum()
    return top_idx, weights
```

`np.argsort(logits)[::-1][:k]` gets the top-`k` indices: `argsort` returns indices in ascending order, `[::-1]` reverses that to descending (highest logit first), and `[:k]` keeps only the first `k`. The critical detail the task description calls out — softmax over *just the selected experts*, not the full set — is why `top_logits - np.max(top_logits)` only ever sees those `k` values: if you instead ran softmax over all 5 logits and then only kept indices 1 and 4, the two weights wouldn't sum to 1 anymore (there'd be "missing" probability mass sitting on the un-selected experts), which would silently break every downstream computation that assumes the gating weights of the *chosen* experts form a real probability distribution.

Real MoE layers (like the ones referenced in [Foundation Model Internals](/docs/llms-genai/foundation-model-internals#mixture-of-experts-moe)) do exactly this per token, independently, at every MoE layer in the network — different tokens can and do route to entirely different experts, which is the whole mechanism that lets specialization emerge (e.g. certain experts becoming better at code, or at a particular language) without anyone hand-assigning which expert handles what.
