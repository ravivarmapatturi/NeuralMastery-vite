# Grouped Query Attention (GQA) From Scratch

**Difficulty: Hard** · Concept: [Foundation Model Internals — Attention Variants: MHA, GQA, MQA, MLA](/docs/llms-genai/foundation-model-internals#attention-variants-mha-gqa-mqa-mla)

Standard multi-head attention (MHA) gives every query head its own key/value head. GQA sits between MHA and multi-query attention (MQA, where *every* query head shares one single key/value head): query heads are split into groups, and all the heads within a group share one key/value head. Fewer, shared K/V heads means a much smaller KV cache to store during generation — the real, practical reason GQA is standard in LLaMA 2/3, Mistral, and most current serving-efficient LLMs, trading a small amount of quality for a large memory/bandwidth win.

**Your task**: implement `grouped_query_attention(Q, K, V, num_kv_groups)` where `Q` has shape `(num_heads, seq_len, d)` and `K, V` have shape `(num_kv_groups, seq_len, d)` — query head `h` should use key/value group `h // (num_heads // num_kv_groups)`.

<Solution>

```python
import numpy as np

def grouped_query_attention(Q, K, V, num_kv_groups):
    num_heads, seq, d = Q.shape
    heads_per_group = num_heads // num_kv_groups
    out = np.zeros_like(Q)
    for h in range(num_heads):
        g = h // heads_per_group
        scores = Q[h] @ K[g].T / np.sqrt(d)
        scores = scores - np.max(scores, axis=-1, keepdims=True)
        weights = np.exp(scores)
        weights /= weights.sum(axis=-1, keepdims=True)
        out[h] = weights @ V[g]
    return out
```

`h // heads_per_group` is the entire grouping logic: with 4 query heads and 2 kv groups, `heads_per_group = 2`, so heads `0, 1` both map to group `0 // 2 = 0` and `1 // 2 = 0`, while heads `2, 3` both map to group `1`. Everything *inside* the loop — the scaled dot product, the numerically-stable softmax (max-subtraction, same trick as [softmax from scratch](/practice/softmax)), and the weighted sum over `V` — is exactly standard single-head attention; GQA is a change to *which K/V a head reads from*, not a change to the attention computation itself. Setting `num_kv_groups=1` (every head sharing one single K/V) recovers multi-query attention (MQA) exactly, and setting it equal to `num_heads` (every head gets its own group) recovers standard MHA — GQA is genuinely the general case both older variants sit inside of, not a separate third algorithm.

A real production implementation wouldn't literally loop over heads in Python (it'd broadcast/repeat the K/V heads to match Q's head count and do one batched matmul) — this loop version is deliberately the clearest way to see *which* K/V each head reads, not the fastest.
