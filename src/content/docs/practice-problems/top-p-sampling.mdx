# Top-p (Nucleus) Sampling From Scratch

**Difficulty: Medium** · Concept: [Foundation Model Internals — Sampling: From Logits to a Token](/docs/llms-genai/foundation-model-internals#sampling-from-logits-to-a-token)

Top-k sampling keeps a fixed number of candidate tokens at every step, which is awkward: a genuinely confident prediction (one token overwhelmingly likely) still keeps `k` candidates even if the rest have almost no probability, while a genuinely ambiguous prediction (probability spread thin across many tokens) is forced down to the same fixed `k`. Top-p (nucleus) sampling fixes this by keeping the *smallest* set of tokens whose cumulative probability exceeds a threshold `p` — the set size adapts automatically to how peaked or flat the distribution actually is, which is why top-p is generally preferred over a fixed top-k in production systems.

**Your task**: implement `top_p_filter(probs, p)` for a 1D array of token probabilities (already summing to 1), returning a same-shape array with every token outside the top-p nucleus zeroed out and the remaining probabilities renormalized to sum to 1.

<Solution>

```python
import numpy as np

def top_p_filter(probs, p):
    order = np.argsort(probs)[::-1]
    sorted_probs = probs[order]
    cumulative = np.cumsum(sorted_probs)
    cutoff = min(np.searchsorted(cumulative, p) + 1, len(probs))
    kept_idx = order[:cutoff]
    filtered = np.zeros_like(probs)
    filtered[kept_idx] = probs[kept_idx]
    filtered /= filtered.sum()
    return filtered
```

`order` sorts token indices from most to least probable, and `cumulative = np.cumsum(sorted_probs)` gives the running total as you walk down that sorted list — `cumulative[0]` is just the top token's probability, `cumulative[1]` is the top two combined, and so on. `np.searchsorted(cumulative, p)` finds where `p` would need to be inserted to keep `cumulative` sorted, which is exactly the index of the first prefix whose cumulative probability reaches `p` — add 1 because `searchsorted` returns a *count of elements before* that point, not the point's own index, and the `min(..., len(probs))` guards the edge case where `p` is so close to 1 that floating-point cumulative sums never quite reach it.

Zeroing out everything outside `kept_idx` and then dividing by the new (smaller) sum is the renormalization step: without it, the kept tokens' probabilities would still sum to whatever fraction of the original distribution they captured (e.g. `0.8`, not `1.0`) — which would silently be an invalid probability distribution to sample from. [Foundation Model Internals](/docs/llms-genai/foundation-model-internals#sampling-from-logits-to-a-token) covers where this fits alongside temperature and greedy decoding in the full sampling pipeline; this function deliberately stops at producing the filtered *distribution*, not drawing the actual random sample, so its behavior stays fully deterministic and testable.
