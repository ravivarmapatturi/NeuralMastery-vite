# Apply Insert/Delete Operations to a Vector Index

**Rank #457** · Difficulty: **Medium** · Stage: **Stage 8: RAG, Agents, MCP & Distributed Systems** · Category: **Agents, MCP & Systems**

Implement `apply_index_operations(operations)`, tracking which vector IDs remain live after a sequence of insert/delete operations -- the bookkeeping behind tombstone-based deletion, since many real ANN indexes (HNSW in particular) don't support true in-place removal. Prerequisite: `agents-mcp-systems-prob-26`.

<PracticePlayground problemId="agents-mcp-systems-prob-27" />

<Solution>

```python
def apply_index_operations(operations):
    live = set()
    for op in operations:
        kind, doc_id = op[0], op[1]
        if kind == "insert":
            live.add(doc_id)
        elif kind == "delete":
            if doc_id not in live:
                raise ValueError(f"cannot delete non-existent id: {doc_id!r}")
            live.remove(doc_id)
        else:
            raise ValueError(f"unknown operation: {kind!r}")
    return sorted(live)
```

This models WHY many real ANN indexes use tombstoning instead of true deletion: physically removing a node from a graph-based index like HNSW is expensive and can break the graph's connectivity, so a "delete" instead just marks an id as dead and filters it from results, with actual removal deferred to a periodic full rebuild.

</Solution>
