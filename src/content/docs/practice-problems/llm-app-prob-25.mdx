# #085. Sliding Window Multi-Tenant Rate Limiter

**Track**: LLM Application Engineering | **Rank**: #85 of 1072 | **Points**: 90 XP

## Overview

Enforce fair multi-tenant API access and quota limits using sliding-window request and token rate limiters. In production LLM application engineering, reliable system components, deterministic interfaces, and defensive validation are paramount for production stability and cost efficiency.

## Task

Implement `check_sliding_window_rate_limit(requests_log, client_id, current_timestamp_sec, window_sec=60, max_requests=10, max_tokens=1000)`. Filter events belonging to `client_id` with timestamps in `[current_timestamp_sec - window_sec + 1, current_timestamp_sec]`. Sum requests count and tokens used. A new request is `allowed: True` if `current_requests < max_requests` and `current_tokens < max_tokens`. If not allowed, compute `retry_after_sec = max(1, (oldest_event_timestamp + window_sec) - current_timestamp_sec)`. Return `{'allowed': bool, 'current_requests': int, 'current_tokens': int, 'retry_after_sec': int}`. Raise `ValueError` if `window_sec <= 0`, `max_requests <= 0`, or `max_tokens <= 0`.
