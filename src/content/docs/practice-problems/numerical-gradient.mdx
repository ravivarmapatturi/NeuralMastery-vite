# Numerical Gradient via Finite Differences

**Difficulty: Medium** · Concept: [Calculus & Optimization — Derivatives and Gradients](/docs/mathematics-for-ai/calculus-optimization#derivatives-and-gradients)

Every analytic gradient on this site — [linear regression's](/docs/practice-problems/gradient-descent-step) $\partial J/\partial w$, backpropagation's chain rule — has an entirely different way to compute (approximately) the same number, with no calculus required: just perturb each input slightly and measure how the output changes. The **central difference** approximation:

$$f'(x) \approx \frac{f(x+h) - f(x-h)}{2h}$$

for a small $h$ (commonly $10^{-5}$). This is slower and only approximate — but it's exactly how you'd sanity-check that a hand-derived analytic gradient (like the one in [One Gradient Descent Step](/docs/practice-problems/gradient-descent-step)) is actually correct, a real technique called **gradient checking**.

**Your task**: implement `numerical_gradient(f, x, h=1e-5)`, where `f` takes a list of numbers and returns a single number, and `x` is the point (a list) to evaluate the gradient at. Return a list — one partial derivative per dimension of `x`.

<Solution>

```python
def numerical_gradient(f, x, h=1e-5):
    grad = []
    for i in range(len(x)):
        x_plus = list(x)
        x_plus[i] += h
        x_minus = list(x)
        x_minus[i] -= h
        grad.append((f(x_plus) - f(x_minus)) / (2 * h))
    return grad
```

For each dimension `i`, hold every other coordinate fixed and nudge only `x[i]` by `+h` and `-h` — that isolates $\partial f/\partial x_i$ specifically, exactly matching what a partial derivative means (rate of change with respect to *one* variable, everything else held constant). Copying `x` into `x_plus`/`x_minus` rather than mutating it in place matters: mutating and restoring is error-prone (easy to forget to undo the change before moving to the next dimension), while fresh copies can't leak state between iterations.

`f(x[0]**2 + x[1]**2)` at `[3, 4]` gives `[6, 8]` — matching the exact analytic gradient $\nabla(x_0^2+x_1^2) = (2x_0, 2x_1) = (6, 8)$, which is the point: central differences approximate the true derivative closely enough (error $O(h^2)$, versus a one-sided/forward difference's $O(h)$) that this is a legitimate correctness check for an analytic implementation, not just a rough estimate. In practice this is exactly how you'd have verified [One Gradient Descent Step's](/docs/practice-problems/gradient-descent-step) `dw`/`db` were implemented correctly, before ever trusting them in a training loop.
